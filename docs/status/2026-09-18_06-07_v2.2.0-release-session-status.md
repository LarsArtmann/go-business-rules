## e) WHAT WE SHOULD IMPROVE

| # | Practice | Impact | Concrete fix |
| --- | --- | --- | --- |
| 1 | **Write the release commit before the daemon does.** | History is the primary artifact of a release; heuristic messages destroy it. | When the user authorizes a release, explicitly commit each logical step first (daemon only picks up leftovers). Consider pausing the daemon for release sessions. |
| 2 | **Add a `release-check` flake app**, mirroring the skill's `pre-release-check.sh`. | Encodes the checklist we just ran by hand (clean tree, no `replace`, tidy/verify, race tests, actionlint, `gh run list` green). | `apps.release-check` in `flake.nix`; refuse to proceed on red. |
| 3 | **Automate the release path**: on `v*` tag push, create the GitHub Release from the CHANGELOG section. | Removes the manual `gh release create` step and the risk of a tag with no release page. | New `.github/workflows/release.yml`. |
| 4 | **Single source of truth for the version.** | One edit instead of two; removes the split brain. | Keep `doc.go` as the source; replace the literal test with a pattern/regexp assertion, or generate the constant. |
| 5 | **Actually use the `buildflow` gate** the project documents. | It is listed as a quality bar but was skipped. | Run `buildflow` before tagging; add it to the release checklist. |
| 6 | **Pin gosec via `tools.go`/`go.mod` tool directive** instead of a loose `go install @version`. | Supply-chain: the version is reproducible, the checksum is in `go.sum`. | `go get -tool github.com/securego/gosec/v2/cmd/gosec@v2.29.0` (Go 1.24+ tool directive) and run `go tool gosec`. |
| 7 | **Re-measure the numbers you publish.** | README claims (coverage 97.1%, 251 specs) are marketing to consumers; stale numbers erode trust. | Regenerate coverage in the release checklist and update README/AGENTS. |
| 8 | **Guard the nested modules structurally.** | A single `git tag` mistake poisons the proxy permanently. | Make `release-check` fail if any tagged module's `go.mod` contains `replace`; document that nested modules are unreleased. |
| 9 | **Add `actionlint` + workflow validation to CI.** | We lint the workflow locally only; a broken workflow can merge. | A `lint-workflows` job running `actionlint`. |
| 10 | **Keep point-in-time docs out of the critical path.** This session produced a wealth of release mechanics that now live only in a timestamped status file. | Future sessions re-derive them. | HARVEST §f into `TODO_LIST.md`/`ROADMAP.md` now (see closing note). |
